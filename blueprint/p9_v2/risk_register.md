# P9 v2 Risk Register

Status: `DRAFT_NON_RUNTIME_NON_AUTHORIZING`

| ID | Risk | Likelihood/impact | Mitigation and acceptance evidence |
|---|---|---|---|
| R1 | Filesystem rename or durability assumptions differ across mounts. | Medium/high | V2-A uses same-filesystem staging, file and directory `fsync`, and 11 synthetic fault boundaries. Production-filesystem power-loss testing remains for V2-H. |
| R2 | Deterministic JSON differs by language/runtime. | Medium/high | V2-A fixes exact binary64 decimal, safe numeric range, NFC UTF-8, and golden Python vectors. Independent-language golden vectors remain required before adding a second writer. |
| R3 | Ledger event volume harms training I/O. | Medium/medium | V2-A uses one bounded segment per durable event and permits progress batching. Benchmark cadence before controller authority in V2-H. |
| R4 | A validation metric exists without a durable checkpoint. | Medium/high | Candidate schema requires checkpoint hashes and atomic marker; finalizer ignores all other validation records. |
| R5 | Legacy checkpoint deserialization executes unsafe code. | Low/high | V2-D verifies source/payload hashes first and uses PyTorch `weights_only=True`, CPU mapping, and a function-local allowlist limited to five NumPy reconstruction types. It never uses unrestricted load or changes global safe globals. Restricted deserialization still parses untrusted binary structure, so canonical V2-G must retain the integrity gate and pinned environment. |
| R6 | Content-addressed external locator becomes mutable. | Medium/high | V2-B separates namespace/key from physical root and verifies object identity, size, payload hash, and associated manifest hash on every validation. Path alone is invalid. |
| R7 | Two publishers race. | Medium/medium | V2-C acceptance-scoped kernel lock, atomic directory publication, validate-or-return, collision rejection, and concurrent synthetic tests. |
| R8 | Finalizer implementation changes output for same contract. | Medium/high | V2-C binds implementation hash/version in finalization identity and tests deterministic and changed-version identities; migration acceptance must pin the version. |
| R9 | Authority revocation/supersession semantics are underspecified. | Resolved/high | V2-E uses a canonical content-addressed eligibility snapshot with sorted acceptance entries and exact authority binding. V2-G atomically published the authorized snapshot alongside canonical acceptance evidence; missing, ambiguous, superseded, or revoked entries fail closed. |
| R10 | Historical source evidence changes before import. | Low/high | V2-D and V2-G recompute full ordered source inventory; exact pre-approved hashes required. |
| R11 | “Scientific complete” is mistaken for historical run success. | Medium/high | Preserve v1 state verbatim and display both dimensions with legacy annotation in every imported result. |
| R12 | Evaluation data leaks into migration/finalization. | Low/critical | V2-C imports no evaluation/training stack, accepts only V2-B evidence with consumption zero, binds zero in finalization/acceptance, and rejects additional evaluation fields. |
| R13 | Downstream code retains manual checkpoint fallback. | High/high | V2-E removes path parameters and adds rejection tests for all five consumers. |
| R14 | V1 remains executable after v2 adoption. | Resolved/high | V2-I reduced all three active target graphs to fail-closed guards, retired eight CLIs plus the recovery controller/resolver, published a hash-bound retirement manifest, and retained only explicit read-only inspection. |
| R15 | Scientific/controller plane imports regress. | Medium/high | Static dependency tests and package/module boundaries; control cannot import parameter-mutating functions and science cannot import acceptance/targets APIs. |
| R16 | V2-C reset patience after a margin-only selected checkpoint, while the dissertation permits reset only for retrieval-loss decrease of at least `1e-4`. | Resolved/high | V2-EF introduced `p9-selection-v2.1.0`, separated selection from patience reset, added boundary/tie regressions, and reconfirmed the unchanged historical epoch-105 selection and epoch-125 stopping boundary. |
| R17 | Duplicate production controllers mutate one scientific run concurrently. | Resolved/high | V2-H uses one scientific-run-key `flock`, deterministic run identity, and a duplicate-start process test; ledger replay, not lock metadata, is truth. |
| R18 | Checkpoint bytes commit but validation linkage tears. | Resolved/high | V2-H publishes payload/manifest first and makes the V2-A event the eligibility point; pre/post-event crash tests converge to zero or one candidate. |
| R19 | Production-shaped pilot accidentally trains or consumes evaluation. | Resolved/critical | V2-H runs under `no_grad`, verifies state digests before/after, and reports zero backward, optimizer, EMA, queue, checkpoint, acceptance, validation, and evaluation counts. |
| R20 | The prompt's flat-removal P9-B labels diverge from the accepted P8/dissertation cumulative comparison design. | Resolved/high | V2-H follows accepted P8 `p8cm_cd7d0f45dd41a7c351ea4d78` and the active dissertation: five nested cumulative A1-A5 templates plus SSV-like and DS-like. Old labels are not routed. |
| R21 | V2-H controller has no executable science worker or checkpoint ACK channel. | Resolved/critical | Remediation adds an independent production worker, deterministic bidirectional protocol, controller-only commit, lost-ACK reconciliation, and real two-GPU update/resume evidence. |
| R22 | P8 and V2 canonical JSON encode finite numbers differently and produce different scientific hashes. | Resolved/high | Native authority binds both hashes explicitly; startup validates the P8 source hash and bundle validation uses the V2 bound-document hash. |
| R23 | Exact resume restores weights but drifts optimizer, queue, RNG, sampler, or traces. | Resolved/critical | Full-state restoration and a fresh-process 2+2 versus uninterrupted 4-update digest comparison cover every required scientific component. Formal power-loss testing remains operational evidence, not a new architecture. |
| R24 | The factor-wise joint hyperparameters interact with `lambda_IP`, or their confirmation is misinterpreted as the overall model selection. | Resolved/high | Exact seed/config/bank audit proved lambda was the sole pairwise difference. IP1 won that scoped comparison, while the overall validation comparison independently selected `cfg_d128`; neither confirmation artifact was invalidated. |
| R25 | A P9-B label routes through a stale cfg_main/selected-FM baseline or loses its final-full-model parent. | Mitigated/critical | Runtime matrix is derived only from `p9bplan_e36f7c9c5069a504eb31a9ef`, binds `cfg_d128` acceptance plus each transformation in scientific identity, and rejects legacy selected-FM plan fields. Sequential formal execution must still stop on any chain mismatch. |
| R26 | DS-like repeatedly rasterizes augmented Shapely geometry in every batch, leaving GPUs idle and making the final comparison disproportionately slow. | Resolved/high | Formal DS input now uses the accepted 78,672-entry per-view cache with manifest, source, payload, shape, dtype, role, scene, and view validation. Representative online/cache rasters are bitwise equal and a four-update two-GPU pilot reduced the estimated epoch wall from about 396 s to 41.3 s. Missing or stale entries fail closed with no online fallback. |
| R27 | A worker interruption after uncheckpointed progress is reported from an `EPOCH_STARTED` boundary and crashes controller bookkeeping or permits an invalid resume. | Resolved/high | Controller reconciliation now searches only committed validation-checkpoint events. The abandoned DS trajectory is closed as operator-requested performance remediation at its epoch-75/update-5,700 durable checkpoint and is policy-forbidden from resume. |
| R28 | Active Fuse contracts retain a superseded dissertation commit or rewrite immutable historical artifacts when methodology authority advances. | Mitigated/critical | One hash-bound refresh authority records the latest dissertation, future P11 uses versioned decision/source contracts, and all historical P9/P10/P11 artifacts remain byte-unchanged. Tests distinguish active authority from historical lineage. |
| R29 | Living-population rematerialization reuses the old complete-support/90% implementation despite the new partial-support methodology. | Resolved/high | The isolated v2 rematerializer explicitly constructs every expected scene-grid-date-hour row, retains unavailable support, publishes `p11ds_39607da2de792ad6b3c9bb30`, and proves all seven non-living targets byte-identical to immutable `p11ds_fdb1f34c6daeda259e803e37`. |
